# 原生安卓在线音乐播放器 · 设计文档（Spec）

- 日期：2026-10-15
- 状态：设计已确认，待转入实现计划

---

## 1. 背景与目标

### 1.1 背景

参考对象是 GitHub 上的开源项目 **Folia（`chthollyphile/folia-major`）**——一个第三方多平台在线音乐客户端，
AGPL-3.0 协议、TypeScript + React + Electron，核心卖点是**绚丽的歌词动画**。

用户希望做一个**同类体验**的安卓播放器，但明确要求：

- **纯原生**，不使用 WebView / Capacitor 之类的套壳方案
- **适配好**，界面与交互针对安卓打磨
- **不使用 API Key / 不需要用户手动配置任何凭证**

### 1.2 目标

做一个**原生安卓在线音乐播放器**，核心体验是：

> 搜索歌曲 → 在线播放 → **逐字歌词动画**（跟得上、不卡顿、有质感）

### 1.3 成功标准

第一阶段的"成功"以**歌词动画的观感**为最高优先级判据：逐字填充跟得上播放进度、不顿、有设计感。

---

## 2. 范围

### 2.1 范围内的（MVP）

本 MVP 只做**纯在线**（用户没有本地音乐库，本地播放能力不在范围内）：

- 搜索（歌曲 / 歌手 / 专辑）
- 在线播放（播放、暂停、上下首、进度拖动）
- 播放队列（顺序 / 单曲循环 / 随机，可查看可删）
- 歌词页：逐字动画、翻译开关、罗马音开关、点行跳转
- 后台播放（通知栏、锁屏、耳机线控）
- 收藏与播放历史
- 登录：游客可用 + 可选扫码登录
- 缓存（歌词缓存、播放地址短期缓存）

**首版只接网易云一个音源**（其逐字歌词 YRC 最成熟），QQ / 酷狗留到第二版通过同一接口接入。

### 2.2 明确不做的（非目标）

以下均**不在 MVP 范围**，属于 MVP 之后的候选：

- 本地音乐扫描与本地播放（用户无此需求）
- 歌单管理 / 导入导出
- 桌面歌词、桌面小组件
- 音效 / EQ、无损下载
- 多音源（QQ 音乐、酷狗）——仅预留接口
- 封面取色动态主题、每日推荐、私人 FM

### 2.3 项目定位约束

- 本项目**定位为个人自用**，不对外发布、不上架应用商店。
- 原因：使用的第三方接口非官方授权，属于灰色地带，且随时可能失效。

## 3. 平台与技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | Kotlin | 安卓原生 |
| UI | Jetpack Compose | 声明式，便于做动画 |
| 播放引擎 | AndroidX Media3 / ExoPlayer | 支持流式播放、无缝切歌 |
| 后台播放 | Media3 `MediaSessionService` | 通知栏 / 锁屏 / 耳机线控 |
| 持久化 | Room | 收藏、播放历史、歌词缓存 |
| 设置 | DataStore | 偏好项 |
| 二维码 | ZXing | 扫码登录的二维码生成 |
| 构建 | Gradle（命令行） | 本机已具备 Android SDK 与 JDK，无需 Android Studio |

**构建结构：先使用单个 Gradle 模块，内部严格分包**，等规模上升再考虑多模块拆分。
理由是避免在早期引入多模块构建的复杂度。

**版本基线建议**：`minSdk 26`、`compileSdk 36`（本机已安装 `android-36` / `android-37`）。

## 4. 整体架构

### 4.1 分层

```text
ui/       Compose 界面：首页、搜索、播放页、歌词页、设置
lyric/    歌词解析(LRC/YRC) + 时间轴 + 逐字动画引擎
player/   播放控制：包装 ExoPlayer，对外暴露"高精度进度时钟"
source/   MusicProvider 接口 + 网易云实现(签名/接口) + 备用源
data/     Room 数据库、DataStore 设置、歌词缓存
model/    统一模型：Song / Artist / LyricLine / LyricWord
```

### 4.2 分层规则

- `ui` 只依赖 `player` 和 `source` 暴露的**接口**，不接触具体实现。
- 所有音源实现同一个 `MusicProvider` 接口，**音源之间互不依赖**。新增音源 = 新增一个实现。
- `model` 可以被任何层依赖，它自身零依赖。
- 不允许跨层反向依赖（例如 `source` 不得依赖 `ui`）。

### 4.3 关键接口契约

`MusicProvider`（音源统一抽象，MVP 只实现网易云）：

```text
search(keyword, type, page) -> Result<List<Song>>
getSongDetail(id)           -> Result<Song>
getStreamUrl(id, quality)   -> Result<StreamInfo>   // 失败须返回明确原因
getLyric(id)                -> Result<LyricData>    // 逐字(YRC) + 译文 + 罗马音
```

`PlayerController`（对 UI 暴露，收敛 ExoPlayer 细节）：

```text
state: StateFlow<PlaybackState>     // 播放状态、当前曲目、队列
positionClock: 逐帧可读的当前播放位置（毫秒精度）
```

## 5. 核心机制：播放 → 歌词逐字动画的数据流

这是本项目的灵魂，架构上的重中之重。

### 5.1 流程

1. 搜索：`Provider.search(关键词)` → `List<Song>`
2. 点播放：`Provider.getStreamUrl(id)`（失败自动切备用源）→ 交给 ExoPlayer
3. 同时：`Provider.getLyric(id)` → 取得 **YRC 逐字歌词** + 翻译 + 罗马音 → 落缓存
4. 解析：把歌词解析成 `LyricTimeline`——每行拆成**每个字自己的时间区间**
5. 渲染：逐帧驱动动画（见 5.2）

### 5.2 动画驱动方式（关键技术决策）

**不能**用播放器的状态回调来驱动逐字动画。ExoPlayer 的状态回调频率只有约 4~10Hz，
用它做逐字动画必然出现明显的阶跃和顿挫。

**正确做法**：在 Compose 中用 `withFrameNanos` 建立一个**逐帧时钟**，每一帧读取
ExoPlayer 的真实播放位置（毫秒精度），据此对每个字的进度做插值。
这样动画与播放进度严格同步，且以 60 / 120Hz 的刷新率渲染。

> 这条是"惊艳"与"廉价"的分界线，也是 Folia 那类效果真正的技术门槛。

### 5.3 歌词降级

逐字歌词不可用时（仅拿到逐行 LRC），降级为整行高亮动画，**不影响播放**。

## 6. 登录策略

登录**完全可选**，不登录也能正常使用。

- **游客模式**：使用内置匿名 cookie。可搜索、可试听；但部分歌曲只有片段、码率被压。
- **可选扫码登录**：
  1. App 内请求登录二维码（用 ZXing 本地生成图片，无需 WebView）
  2. 轮询扫码状态
  3. 成功后保存 `MUSIC_U` 到本地加密存储
  4. 解锁完整播放与高音质
- 播放页对"试听片段"状态做**显式标注**，不让用户误以为是 bug。

---

## 7. 音源接入方案（已选定：方案 1，端上自包含）

在 Kotlin 中**直接实现网易云接口的签名算法**（接口要求 AES + RSA 加密参数；社区有成熟的逆向资料
与现成 JS 实现可供对照移植）。

- **优点**：零服务器、零月费、零第三方依赖；App 完全自包含；接口策略变更只需发版更新。
- **代价**：前期需要先啃下签名部分；调试相对麻烦。

**备用源**（兜底）：一个**地址可在设置中配置的第三方公共接口实例**（默认留空）。
仅在端上签名路径临时失效时启用，作为应急备胎，避免"打开就没歌"。
默认路径始终是端上自包含，备用源不参与正常流程。
具体默认实例地址在 MI-1 阶段确定。

**必须做**

- 搜索：关键词搜索歌曲 / 歌手 / 专辑
- 播放：在线播放、播放暂停、上下首、进度拖动

- 登录：游客可用 + 可选扫码登录
- 缓存：歌词缓存、播放地址短期缓存

**不做**：见 2.2。

## 9. 错误处理

**统一原则**：所有音源调用返回 `Result<T>`（成功 / 失败 + 原因）；
异常**绝不抛到 UI 层**，由 UI 统一呈现。

| 场景 | 处理 |
|---|---|
| 接口失效 / 被限流 | 自动切备用源重试一次；仍失败则提示"音源暂时不可用" + 重试按钮 |
| 无版权 / VIP 受限 | 播放地址为空 → 提示"需登录或暂无版权" + 自动跳到下一首 |
| 未登录只能试听 | 播放页显式标注"试听片段 · 登录解锁完整版" |
| 网络中断 | 缓冲指示 + 自动重连（指数退避，最多 3 次） |
| 歌词拉取失败 | 降级为"暂无歌词"，**绝不影响播放**（歌词是可选层） |
| 签名 / 解析异常 | 写入本地日志文件便于排查；不向用户暴露技术错误 |

## 10. 测试策略

1. **单元测试（最优先）**
   - 签名算法：用"已知输入 → 已知输出"向量验证（对照 JS 实现）
   - 歌词解析：YRC / LRC 各种畸形输入、多行翻译、空行、异常时间戳
   - `LyricTimeline` 查表：给定播放位置返回正确的行与字
   - 接口响应解析：使用固定 JSON 样本，完全离线
2. **集成测试（可选，需联网）**：真实调用网易云接口，手动触发，
   避免让构建流程依赖外部网络。
3. **UI 验证**：Compose Preview + 真机/模拟器手动走完关键链路
   （搜索 → 播放 → 歌词 → 后台 → 锁屏）
4. **性能关注点**：逐帧读播放位置的开销、歌词页滚动掉帧、搜索结果长列表滚动

## 11. 开发里程碑

顺序是刻意设计的：**最危险的（签名）放在最前面验证**，不通则尽早发现，避免白做。

| 里程碑 | 内容 | 完成标准（可验证） |
|---|---|---|
| **MI-1 打通接口** | 项目骨架 + 搜索功能 | App 能启动，输入关键词能列出真实搜索结果（签名算法成败的关键节点） |
| **MI-2 能放歌** | 在线播放 + 播放页 + 队列 + 后台/通知栏 | 点歌能出声；切后台不断；通知栏能控制 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 网易云接口签名/协议变更 | 全部在线能力失效 | 端上自包含便于快速发版修复；备用源可切换兜底 |
| 第三方接口非官方授权 | 法律灰色地带 | 项目定位个人自用，不发布、不上架 |
| 游客模式音质/试听受限 | 体验预期落差 | 显式标注状态；扫码登录解锁（可选） |
| 逐字歌词版权 | 歌词展示的合规性 | 与音频分离，歌词失败即降级，不影响播放 |
| 本机缺 Android 模拟器组件 | 无法运行调试 | 见 13；到 MI-1 前解决 |
